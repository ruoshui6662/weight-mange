# 今日页浏览器可用性审计（2026-09-13）

任务 ID：DOC-009  
审计对象：`http://127.0.0.1:4173/` 今日页  
捕获工具：Codex In-app Browser（当前浏览器标签）  
数据：隔离的本地 E2E 数据库；创建 `audit-user`，设置目标 1800 kcal，写入早餐馒头 80g。  

## 结论

今日页核心闭环可用，当前状态为“可用但需要体验修正”。热量摘要、零值语义、四餐入口、弹窗搜索、份量写入、汇总刷新和返回焦点均按预期工作。主要风险不是数据链路，而是首屏主操作需要滚动、空餐文案与布局不一致，以及弹窗对屏幕阅读器和键盘的隔离不完整。

## 测试步骤与证据

### 1. 首次设置

- 操作：填写称呼、12+ 位测试密码，提交；填写身高 170 cm，保存目标。
- 结果：通过。设置页字段完整，提交后进入今日页。
- 视觉证据：本次浏览器捕获截图“首次设置”“目标设置”。
- 无障碍：称呼、密码、时区、身高等字段均有可读标签；按钮可聚焦。

### 2. 今日空态与热量卡

- 结果：通过。已摄入为 `0 kcal`，目标为 `1800 kcal`，环中心显示还可以吃 `1800 kcal`，完成度为 `0%`；宏量显示 `0 g` 和“暂无目标”，没有用 0 冒充目标。
- 视觉证据：本次浏览器捕获截图“今日页初始状态”。
- 发现：1280×720 视口中热量卡占据首屏大部分高度，今日饮食卡标题在首屏底部，四个添加按钮需要滚动后才能看到。

### 3. 今日饮食记录区

- 结果：通过。早餐、午餐、晚餐、加餐四张卡均有独立“添加”按钮；早餐写入后显示 `178 kcal` 和“馒头 · 80g”，编辑/删除按钮出现。
- 视觉证据：本次浏览器捕获截图“今日饮食记录空态”“早餐写入后”。
- P1 体验问题：空餐卡文案为“还没有记录 · 从下方快速添加一项”，实际入口在卡片右上角，不存在“下方快速添加”区域，容易造成寻找错误。
- P2 体验问题：四个空餐卡都重复同一句说明，信息密度偏高；可改为卡片级短文案，统一由卡片标题下的说明承担引导。

### 4. 餐次添加弹窗

- 操作：点击早餐、午餐、晚餐添加按钮。
- 结果：通过。弹窗标题和 `当前添加到` 与所点餐次一致；午餐现场验证为“添加午餐/当前添加到：午餐”，晚餐同理。
- 视觉证据：本次浏览器捕获截图“添加早餐弹窗”“添加午餐弹窗”“晚餐无结果弹窗”。
- 结果：搜索框自动获得焦点；输入“馒头”返回本地结果；选择结果后出现餐次、份量和“加入早餐”确认区。
- P1 可访问性风险：AX 树在弹窗打开时仍包含背景页面的导航、餐次按钮和删除按钮。`aria-modal` 已声明，但未对背景内容设置 `inert` 或等效焦点隔离；键盘/屏幕阅读器可能访问到被遮罩内容。
- P1 可访问性风险：没有焦点陷阱。当前打开弹窗后焦点能进入搜索框，关闭后能恢复到触发按钮，但 Tab 继续时可能离开弹窗。
- P2 交互问题：选择食物后焦点仍停留在搜索框，没有自动转到份量输入；键盘用户需要额外多次 Tab。

### 5. 搜索无结果与恢复

- 操作：在晚餐弹窗搜索“不存在的食物”。
- 结果：通过。显示“没有找到匹配食物”、说明当前仅搜索本地目录，并提供“查看导入说明”。
- 视觉证据：本次浏览器捕获截图“晚餐无结果弹窗”。
- P2 体验建议：无结果区域可补充“清空搜索”或“换一个关键词”次级动作，减少用户只能关闭弹窗重试的感觉。

### 6. 写入后刷新与关闭

- 操作：早餐选择馒头，份量改为 80g，提交；关闭午餐弹窗。
- 结果：通过。弹窗关闭，今日热量刷新为 178 kcal/10%，早餐卡显示馒头 80g；关闭午餐后焦点恢复到“添加午餐食物”按钮。
- 视觉证据：本次浏览器捕获截图“早餐写入后”“关闭午餐弹窗”。
- 数据边界：本次没有覆盖服务端写入失败、会话过期和刷新失败；这些由现有 E2E/单元门禁覆盖，不作为本次浏览器现场结论。

## 修复规划

### P0

本次未发现阻断今日页使用的 P0 问题。

### P1（建议下一轮优先）

1. **DOC-010 空餐引导文案统一**：将“从下方快速添加一项”改为“点击右上角‘添加’开始记录”，并移除重复的“快速”措辞；补 TodayPage 文案回归测试。
2. **M3-026 弹窗焦点隔离**：打开弹窗时将背景主容器标记 `inert`，实现 Tab 循环、首焦点/末焦点闭环，并保留关闭后的触发按钮焦点恢复；增加键盘 E2E。
3. **M3-027 首屏主任务可见性**：在不恢复重复快捷记录区的前提下，压缩桌面热量卡垂直占用或将今日饮食卡上移，确保 1280×720 首屏至少露出第一行餐次添加按钮；以真实视口截图复核，不牺牲热量/宏量层级。

P1 执行结果（2026-09-13）：DOC-010、M3-026、M3-027 均已完成。空餐文案已指向当前餐次“添加”按钮；弹窗背景已设置 inert/aria-hidden，Tab/Shift+Tab 循环且关闭后恢复触发焦点；桌面热量卡已紧凑化，1280×720 首屏可见第一餐添加入口。详见 `DEVELOPMENT_PROGRESS.md` 中对应任务及 EVD-DOC-010-A/EVD-M3-026-A/EVD-M3-027-A。

### P2（随后优化）

1. 选择食物后自动聚焦份量输入，并用状态提示播报“已选择 X，默认 100g”。
2. 无结果状态补充“清空搜索/修改关键词”次级动作。
3. 移动端将餐次 `<select>` 改为可读的 Radio list 或分段控件，确认按钮保持在 Sheet 可见区域。
4. 对四餐空卡减少重复说明，提升窄屏信息密度。
